2 When it shows, and when it stops

The daemon decides. The page only shows what the daemon reports and sends back what was clicked.

Shows when

  • The daemon was first used 7 or more days ago. The time is first_used in ~/.cookie-agent/star.json, written the first time the daemon starts.
  • The flag file has no done entry yet, and snoozed_until, if any, has passed.
  • The page is the owner's, not a guest's on a shared session.

Never again once

  • Star was clicked, whether starring worked or GitHub opened instead: done: "starred".
  • Don't remind me was clicked: done: "dismissed".
  • Later or × only hides it: snoozed_until = now + 7 days.
  • GitHub says the signed-in account already starred the repo: done: "already", without showing anything.

What Star does

  • A GitHub account is signed in on the daemon's machine (gh auth token, or GH_TOKEN / GITHUB_TOKEN): the button reads Star as @login, and the daemon stars with PUT /user/starred/cookie-agent/cookie-agent.
  • No account: the button is a link that opens the repo in a new tab.
  • Starring fails (e.g. a fine-grained token without the Starring permission): the card offers the link instead.
Flag file and checks 
// ~/.cookie-agent/star.json
{ "first_used": "2026-11-20T09:12:00Z",
  "snoozed_until": null,         // set by Later or ×
  "done": null }                 // {"how": "starred" | "dismissed" | "already", "at": …}

// the starred check: once a day at most, only once 7 days have passed
gh api /user/starred/cookie-agent/cookie-agent   // 204 starred, 404 not
// starring
gh api -X PUT /user/starred/cookie-agent/cookie-agent
The check and the star go to GitHub only with a token that is already on the machine, and only after 7 days. The daemon sends no network request before that.
